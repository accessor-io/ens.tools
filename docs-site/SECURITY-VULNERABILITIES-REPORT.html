Security Vulnerabilities Report

Date: 2025-01-11 Scope: Full codebase security audit Severity Levels: Critical, High, Medium, Low

Critical Vulnerabilities

1. SSL Certificate Validation Disabled in Production

Location: server/db/index.ts:6 Severity: Critical Description: SSL certificate validation is explicitly disabled for database connections in production, making the application vulnerable to man-in-the-middle attacks. Vulnerable Code: 
Impact: Attackers can intercept database connections and potentially steal credentials or manipulate data.

Recommendation: Enable certificate validation and provide proper CA certificate:
typescript ssl: process.env.NODE_ENV === 'production' ? { rejectUnauthorized: true, ca: fs.readFileSync(process.env.DB_CA_CERT_PATH).toString() } : false, 
---


2. JWT Token Verification Bypass

Location: server/api/middleware/auth.ts:31  
Severity: Critical  
Description: The JWT token is manually parsed and decoded without verifying the signature. An attacker can forge tokens by creating a valid-looking JWT without knowing the secret.

Vulnerable Code:
31:31:server/api/middleware/auth.ts const payload = JSON.parse(Buffer.from(token.split('.')[1], 'base64').toString()); 
Impact: Complete authentication bypass - attackers can impersonate any user by crafting a JWT with any address.

Recommendation: Use a proper JWT library (e.g., jsonwebtoken) to verify signatures:
typescript import jwt from 'jsonwebtoken'; const payload = jwt.verify(token, process.env.JWT_SECRET || 'dev-secret'); 
---


3. SQL Injection via Dynamic Query Construction

Location: server/api/routes/contracts.ts:101-108  
Severity: Critical  
Description: The PUT endpoint constructs SQL dynamically using object keys without validation, allowing SQL injection if malicious keys are provided.

Vulnerable Code:
101:108:server/api/routes/contracts.ts const setClause = Object.keys(updates) .map((key, index) => ${key} = $${index + 2}) .join(', '); const result = await db.query( UPDATE contracts SET ${setClause} WHERE id = $1 AND user_id = $2 RETURNING *, 
Impact: SQL injection allowing data exfiltration, modification, or deletion.

Recommendation: Whitelist allowed column names:
typescript const ALLOWED_FIELDS = ['name', 'ens_name', 'chain', 'type', 'status', ...]; const setClause = Object.keys(updates) .filter(key => ALLOWED_FIELDS.includes(key)) .map((key, index) => ${key} = $${index + 2}) .join(', ');

4. Weak JWT Secret with Default Fallback

Location: server/api/routes/auth.ts:80  
Severity: High  
Description: JWT secret defaults to 'dev-secret' if environment variable is not set, making tokens easily forgeable in production.

Vulnerable Code:
80:80:server/api/routes/auth.ts .createHmac('sha256', process.env.JWT_SECRET || 'dev-secret') 
Impact: If JWT_SECRET is not set, tokens can be forged by anyone.

Recommendation: Fail fast if JWT_SECRET is not set in production:
typescript const secret = process.env.JWT_SECRET; if (!secret && process.env.NODE_ENV === 'production') { throw new Error('JWT_SECRET must be set in production'); } 
---


5. Missing Input Validation on API Routes

Location: Multiple routes in server/api/routes/  
Severity: High  
Description: Most API routes accept user input without validation of types, sizes, or formats.

Examples:

  • server/api/routes/contracts.ts:37-56 - No validation of address format, name length, metadata size
    • 

  • server/api/routes/audit-log.ts:35 - No validation of action, target, or metadata fields
    • 

  • server/api/routes/config.ts:73 - No validation of config object size or structure
    • 

Impact: 

  • DoS via large payloads
    • 

  • Data corruption
    • 

  • Memory exhaustion
    • 

Recommendation: Implement input validation middleware using a library like zod or joi:
    typescript import { z } from 'zod'; const contractSchema = z.object({ address: z.string().regex(/^0x[a-fA-F0-9]{40}$/), name: z.string().max(255), metadata: z.record(z.any()).optional(), });

Impact: Potential for:

  • Information disclosure via error messages
    • 

  • Race conditions
    • 

  • Unauthorized access attempts
    •

    9. No CSRF Protection
    
Location: server/api/index.ts  
Severity: Medium  
Description: No CSRF tokens or SameSite cookie protection implemented for state-changing operations.

Impact: Cross-site request forgery attacks can perform actions on behalf of authenticated users.

Recommendation: 

  • Implement CSRF tokens for state-changing requests
    • 

  • Use SameSite cookies
    • 

  • Consider using csurf middleware
    • 


    


    10. Rate Limiting Only IP-Based
    
Location: server/api/index.ts:26-31  
Severity: Medium  
Description: Rate limiting is only based on IP address, which can be easily bypassed with proxies or VPNs.

Vulnerable Code:
    26:31:server/api/index.ts const limiter = rateLimit({ windowMs: 15 60 1000, // 15 minutes max: 100, // limit each IP to 100 requests per windowMs message: 'Too many requests from this IP, please try again later.', }); 
    Impact: DoS attacks via distributed IPs or proxy rotation.

Recommendation: 

  • Add user-based rate limiting (per authenticated user)
    • 

  • Implement progressive rate limiting
    • 

  • Use Redis for distributed rate limiting
    •
