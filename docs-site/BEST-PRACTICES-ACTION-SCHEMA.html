Best Practices: ENS Action Schema System

Overview

This document outlines best practices for using the ENS Action Schema System to manage ENS domains efficiently and securely.

      • Action File Organization

      1. Use Clear File Naming

      Name your action files descriptively:

      ✅ Good:

    • complete-domain-setup.txt
      • 

    • batch-metadata-update-2024-01.txt
      • 

    • subdomain-structure-v2.txt
      • 

❌ Bad:

    • actions.txt
      • 

    • temp.txt
      • 

    • file1.txt

      • 2. Organize Actions Logically

      Group related actions together with comments: 
      # ============================================

      Domain Setup
      

      ============================================
      


      Wrap domain
      
+wrap: [example.eth]@domain = [0x742d...]@owner


      Set resolver
      
setResolver: [example.eth]@domain = [0x231b...]@resolver


      ============================================
      

      Address Configuration
      

      ============================================
      

setAddr: [example.eth]@domain = [0x742d...]@address


      ============================================
      

      Metadata
      

      ============================================
      

setText: [example.eth]@domain@[description]@key = [My domain]@value
setText: [example.eth]@domain@[url]@key = [https://example.com]@value

      3. Use Comments Liberally

      Add comments to explain complex operations: 
      # Set up delegation with subdomain management and text record permissions

      Permission bitmask: 1 (MANAGE_SUBDOMAINS) + 4 (SET_TEXT_RECORD) = 5
      
+delegateTo: [example.eth]@domain = [0x742d...]@delegate@[5]@permissions

      Syntax Best Practices

      1. Always Use Brackets for Values

      ✅ Good: setText: [example.eth]@domain@[description]@key = [My domain]@value
❌ Bad: setText: example.eth@domain@description@key = My domain@value

      2. Use Consistent Spacing

      ✅ Good: setText: [example.eth]@domain@[description]@key = [My domain]@value
❌ Bad: setText:[example.eth]@domain@[description]@key=[My domain]@value

      3. Validate Addresses Before Use

      Always verify addresses are correct before including in action files: 
      # Verify this address on Etherscan before using
setAddr: [example.eth]@domain = [0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb]@address

      4. Use Full Domain Names

      ✅ Good: setText: [example.eth]@domain@[description]@key = [My domain]@value
❌ Bad: setText: [example]@domain@[description]@key = [My domain]@value

      Security Considerations

      1. Review Actions Before Execution

      Always review parsed actions before executing:
    • Check all domain names are correct
    • Verify all addresses are valid
    • Confirm parameter values match expectations
    • Review permission settings for delegation

      • 2. Test with Small Batches First

      Start with 2-3 actions to test your workflow: 
      # Test batch
setText: [example.eth]@domain@[description]@key = [Test]@value
setText: [example.eth]@domain@[url]@key = [https://test.com]@value
      Then scale up once confirmed working.

      3. Use Templates for Repetitive Operations

      Templates reduce errors from manual entry: 
      # Use template instead of manually typing

      Template: complete-domain-setup.txt

      4. Verify Permissions

      Before delegating, verify:
    • You have permission to delegate
    • Delegate address is correct
    • Permission levels are appropriate
    • Expiration dates are set if needed

      • 5. Double-Check Critical Operations

      For critical operations (transfers, wraps, fuses), always:
    • Review twice
    • Test on testnet first if possible
    • Have a rollback plan

      • Gas Optimization

      1. Batch Related Operations

      Group related operations together: 
      # All metadata updates in one batch
setText: [example.eth]@domain@[description]@key = [My domain]@value
setText: [example.eth]@domain@[url]@key = [https://example.com]@value
setText: [example.eth]@domain@[avatar]@key = [https://example.com/avatar.png]@value

      2. Order Actions by Gas Cost

      Place lower gas operations first when possible: 
      # Text records (lower gas) first
setText: [example.eth]@domain@[description]@key = [My domain]@value


      Then address records (medium gas)
      
setAddr: [example.eth]@domain = [0x742d...]@address


      Finally complex operations (higher gas)
      
+wrap: [example.eth]@domain = [0x742d...]@owner

      3. Avoid Redundant Operations

      Don't set the same value twice: 
      ❌ Bad:
setText: [example.eth]@domain@[description]@key = [My domain]@value
setText: [example.eth]@domain@[description]@key = [My domain]@value

✅ Good:
setText: [example.eth]@domain@[description]@key = [My domain]@value

      Error Prevention

      1. Validate Domain Names

      Ensure domain names are:
    • Fully qualified (include .eth)
    • Correctly spelled
    • Owned by you

      • 2. Check Address Format

      All addresses must be:
    • Valid Ethereum addresses (42 characters, starts with 0x)
    • Checksummed when possible
    • Verified on blockchain explorer

      • 3. Verify Parameter Types

    • Numbers should be integers
    • Timestamps should be Unix timestamps
    • Booleans should be true or false

      • 4. Test Parsing First

      Before executing, verify actions parse correctly:
    • Upload file
    • Review parsed actions
    • Check for errors
    • Then execute

      • Template Usage

      1. Start with Pre-built Templates

      Use provided templates as starting points:
    • complete-domain-setup.txt
    • subdomain-structure.txt
    • batch-metadata-update.txt
    • delegation-setup.txt

      • 2. Customize Templates

      Modify templates for your needs:
    • Copy template
    • Replace variables
    • Add/remove actions
    • Save with descriptive name

      • 3. Create Your Own Templates

      For repetitive tasks, create custom templates: 
      # my-custom-template.txt

      Description: Sets up project subdomains with metadata
      

+mintSubdomain: [{{subname}}]@subname@[{{parent}}]@parent = [{{owner}}]@owner
setText: [{{subname}}.{{parent}}]@domain@[description]@key = [{{description}}]@value

      Version Control

      1. Track Action Files

      Keep action files in version control: 
      git add actions/complete-domain-setup.txt
git commit -m "Add complete domain setup action file"

      2. Document Changes

      Include changelog comments: 
      # v1.0 - Initial setup

      v1.1 - Added content hash
      

      v1.2 - Updated resolver address

      3. Tag Releases

      Tag action file versions: 
      git tag -a v1.0 -m "Initial action file set"

      4. Backup Before Major Changes

      Before executing major changes:
    • Export current state
    • Backup action files
    • Document expected outcomes

      • Common Patterns

      Pattern 1: Domain Initialization

      # 1. Wrap (if using NameWrapper)
+wrap: [example.eth]@domain = [0x742d...]@owner


      2. Set resolver
      
setResolver: [example.eth]@domain = [0x231b...]@resolver


      3. Set address
      
setAddr: [example.eth]@domain = [0x742d...]@address


      4. Add metadata
      
setText: [example.eth]@domain@[description]@key = [My domain]@value

      Pattern 2: Batch Metadata Update

      # Update all metadata in one transaction
setText: [example.eth]@domain@[description]@key = [Updated description]@value
setText: [example.eth]@domain@[url]@key = [https://new-url.com]@value
setText: [example.eth]@domain@[avatar]@key = [https://new-avatar.png]@value

      Pattern 3: Subdomain Creation

      # Create multiple subdomains
+mintSubdomain: [app]@subname@[example.eth]@parent = [0x742d...]@owner
+mintSubdomain: [api]@subname@[example.eth]@parent = [0x742d...]@owner
+mintSubdomain: [www]@subname@[example.eth]@parent = [0x742d...]@owner

      Troubleshooting

      Issue: Actions Not Parsing

      Solution:
    • Check bracket notation syntax
    • Verify all parameters are provided
    • Check for typos in action names
    • Ensure operators are correct

      • Issue: Transaction Fails

      Solution:
    • Check you have permissions
    • Verify domain ownership
    • Ensure sufficient gas
    • Review error in audit log

Issue: Call Data Not Highlighting

Solution:
  • This is normal for some complex actions
  • Full call data is always available
  • Highlighting is approximate for display
