Granular Permissions Integration

Summary

Granular permission functionality has been fully integrated into the config application. This implementation enables fine-grained, time-bound delegation of ENS domain operations using the ENSIP GNA (Granular Name Assignment) specification.

What Was Built

1. Service Layer (src/lib/services/granular-permission-service.ts)

Service for interacting with the ENSNamingDelegateGranular contract:

  • Core Functions:

    • - addDelegate() - Add a delegate with specific permissions - removeDelegate() - Remove a delegate - updateDelegate() - Update delegate permissions - isAuthorizedDelegate() - Check if delegate is authorized for an operation - getDelegateInfo() - Get delegate information - getPermissions() - Get permissions bitmask for a delegate

  • Permission Management:

    • - lockDelegate() / unlockDelegate() - Lock/unlock delegates - enableDelegate() / disableDelegate() - Enable/disable delegates - emergencyPause() - Emergency pause for a node

  • Utility Functions:

    • - parsePermissions() - Convert bitmask to human-readable array - buildPermissions() - Build bitmask from permission names - getAllPermissions() - Get all available permissions with labels

    2. UI Component (src/components/delegation/GranularPermissions.tsx)

    UI component for managing granular permissions:

  • Features:

    • - View all delegates for a domain - Add new delegates with permission selection - Remove delegates (if not locked) - Lock/unlock delegates - Enable/disable delegates - Emergency pause functionality - Permission bitmask builder with checkboxes - Expiration date management - Visual indicators for locked, disabled, and expired delegates

  • Permission Selection:

    • - Checkbox interface for all 11 permission types - Permission descriptions and labels - Visual permission list

    3. Integration with Existing Systems

    Permission Service (src/lib/delegation/permission-service.ts)

  • Added checkGranularPermission() method
  • Updated checkPermissions() to detect granular permissions
  • Added granular recommendation type
  • Returns granular permission information in PermissionCheckResult

    • Delegation Planner (src/lib/delegation/delegation-planner.ts)

  • Added support for granular delegation type
  • Handles existing granular permissions
  • Stores granular permission metadata in delegation plans

    • 4. Domain Profile Integration

    Added "Permissions" tab to DomainProfile.tsx:

  • Accessible from domain management interface
  • Integrated with existing domain operations
  • Shows granular permissions alongside other domain settings

    • 5. Contract ABIs (src/lib/ens/granular-contracts.ts)

    Exported ABIs for:

  • ENSNamingDelegateGranular
  • GranularResolver

    • Permission Types

    The system supports 11 granular permission types:

    1. MANAGE_SUBDOMAINS (1) - Create and manage subdomains
    2. SET_ADDR_RECORD (2) - Set address records
    3. SET_TEXT_RECORD (4) - Set text records
    4. SET_CONTENT_HASH (8) - Set content hash
    5. SET_PUBKEY (16) - Set public key
    6. SET_ABI (32) - Set ABI data
    7. SET_ZONEHASH (64) - Set zone hash
    8. SET_TTL (128) - Set TTL
    9. SET_RESOLVER (256) - Set resolver
    10. SET_OWNER (512) - Set owner (Registry operations)
    11. SET_FUSES (1024) - Set fuses (NameWrapper operations)

      12. Usage

      Adding a Delegate

    12. Navigate to a domain in DomainProfile
    13. Click the "Permissions" tab
    14. Click "Add Delegate"
    15. Enter delegate address
    16. Select permissions using checkboxes
    17. Optionally set expiration date
    18. Click "Add Delegate"

      19. Checking Permissions

      The permission service automatically checks for granular permissions when:

    19. Checking contract permissions
    20. Creating delegation plans
    21. Verifying authorization

      22. Integration Points

    22. Preflight Checker: Can detect granular permissions
    23. Delegation Planner: Uses granular permissions when available
    24. Permission Service: Checks granular permissions alongside other patterns

      25. Configuration

      Contract Address

      The granular permission service requires the deployed ENSNamingDelegateGranular contract address:

      granularPermissionService['contractAddress'] = '0x...' as Address;
      Or pass it to the component: 
      <GranularPermissions 
  domainName="example.eth" 
  contractAddress="0x..." 
/>
